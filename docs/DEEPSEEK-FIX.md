# DeepSeek 接入与 AI 产出质量修复说明

分支：`fix/deepseek-integration`（基于 `main` 的 d9f8c71，InvestAI 2.4.0）

反馈的两个问题：**内容产出不行**、**DeepSeek API 接入有点小问题**。排查下来是同一串原因：模型调用要么直接失败、要么输出被截断，失败后又连带让后面几分钟的 AI 功能全部退回离线引擎（只做原文摘录），所以看到的成果质量很差。

依据的是 DeepSeek 官方文档（[模型与价格](https://api-docs.deepseek.com/quick_start/pricing)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion)、[更新日志](https://api-docs.deepseek.com/updates)，2026-10 版本）。

## 一、问题与根因

| # | 问题 | 根因 | 用户看到的现象 |
|---|---|---|---|
| 1 | 默认模型名不存在 | 代码写的是 `deepseek-v4.1-flash`，官方 ID 是 **`deepseek-flash`**（即 V4.1 Flash；`deepseek-v4-flash` 是暂时兼容的旧名，`deepseek-chat` / `deepseek-reasoner` 已于 2026-07-24 停用） | 按文档会返回 400 Model Not Exist，起草、问答、预审全部退回离线引擎 |
| 2 | 思考模式吃光输出额度 | DeepSeek 默认开启思考模式，`max_tokens` 同时计入思维链和正文；原来的额度很小（规划大纲 1500、起草 6000、预审 1500、问答 1800） | 大纲 JSON 被截断后静默改用固定模板；长报告写到一半被截断，而且没有任何提示；预审常常是空的 |
| 3 | 第二轮对话报 400 | 思考模式下带 `tools` 的请求，要求每条历史 assistant 消息都带 `reasoning_content`。被拒绝的指令（如「帮我表决」）留下的回复以 assistant 消息回放，缺这个字段 | 对话里出现过一次拒绝后，之后的提问全部「智能体不可用」，退回检索 |
| 4 | 一次失败拖垮 5 分钟 | 任何一次失败（包括限流、超时、网络抖动）都把模型标记为不可用 5 分钟 | 偶发一次 503 后，接下来的起草、问答、预审全是离线引擎；换了正确的 Key 也要等 5 分钟 |
| 5 | 设置页无法改 Key | 桌面版保存 Key 后，Key 输入框被替换成写着「来自 DSH」的下拉框，下拉框的选择在桌面版也不生效 | Key 填错后没法在界面上改，也选不了模型 |
| 6 | 智能体没有上下文 | 智能体的回答在对话记录里只存了任务 ID、没有正文，历史里从来没有它自己说过的话 | 追问「那它的风险呢」之类的指代时答非所问 |

顺带发现并修掉的小问题：

- 离线引擎：大纲里有「待核实事项」时，文末又固定再生成一节，报告里出现两遍。
- 离线大纲：从历史 PPT 提取章节时把封面（第 1 页，如「某半导体项目 立项报告」）也当成章节，别的项目的标题会出现在本项目大纲里。
- 设置页表单样式：`.f` 只在弹窗里定义了竖排样式，设置页所有表单项挤在一行。
- `finish()` 里 120 秒的清理定时器没有 `unref`，测试进程跑完要空等约 2 分钟才退出（全量测试从约 140 秒降到约 20 秒）。

## 二、改动

**`core/llm.mjs`（模型适配层，OpenAI 兼容部分重写）**
- 默认模型改为 `deepseek-flash`；新增 `normalizeModel()`，旧设置或环境变量里的 `deepseek-v4.1-flash` / `deepseek-chat` / `deepseek-reasoner` 自动换成 `deepseek-flash`。
- 每次调用带 `reasoning` 参数（`off` / `low` / `high` / `max`），对 DeepSeek 官方接口显式发送 `thinking` 与 `reasoning_effort`；本地 Ollama 等非 DeepSeek 接口不发这些参数。
- `finish_reason: length`：有正文时追加「输出达到长度上限，已截断」；思考阶段就用完额度、没有正文时抛错，交给调用方回落，不再当成空回答。
- 带工具的多轮请求里，assistant 消息始终带 `reasoning_content`；`tools` 为空时不发送。
- 429 / 5xx / 网络错误在开始输出前最多重试 2 次；错误带 `permanent` 标记（Key 无效、余额不足、模型名不存在等配置类错误为 `true`）。
- SSE 流中途返回 `error` 时抛错（以前被静默忽略）。
- `secretLlm` 支持界面里选择的模型（`getModel`）和 `refresh()`（保存 Key 后立即重读）；`models()` 返回可选的 DeepSeek 模型。

**`core/ai.mjs` / `core/agent.mjs` / `core/extract.mjs` / `core/meetings.mjs`（调用点）**

| 调用 | 思考模式 | 额度（旧 → 新） |
|---|---|---|
| 规划大纲 | 关 | 1500 → 3000 |
| 起草成果 | 开（high） | 6000 → 32000 |
| 智能体每一步 | 开（high） | 6000 → 32000 |
| 问答 | 开（low） | 1800 → 8000 |
| 提交预审 | 开（low），超时 120 → 180 秒 | 1500 → 8000 |
| 混合模式公开资料提炼 | 关 | 1200 → 4000 |
| 智能提取 / 会议纪要（JSON） | 关 | 2500 / 2000 → 6000 |

- 新增 `noteFailure()`：只有配置类错误才在 5 分钟内改走离线引擎；暂时性错误只记录为「最近一次出错」，下次照常调用。新增 `resetHealth()`：保存 Key 或模型设置后清除失败记录。
- 新增 `testModel()` 与接口 `ai.test`（需要「AI 策略」权限）：发一条很短的请求，验证 Key、模型名与网络。
- 智能体：最近几轮对话（含智能体自己的回答正文）作为背景文字放进本轮提问，不再以 assistant 消息回放。`runAgent` 的参数 `history` 改为 `context`（字符串）。
- 资料长度：每份资料保留 3 万字原文，送进提示词时外部模型（DeepSeek 上下文 1M）每份 2 万字，本地模型仍为 7000 字。
- 因密级策略走离线时，离线报告开头说明原因和调整方法（这是策略，不是故障）。

**`core/http.mjs` / `core/api.mjs`**
- 桌面版 / 服务端使用界面里选择的 DeepSeek 模型（设置了环境变量 `INVESTAI_LLM_MODEL` 时以环境变量为准）。
- 保存 DeepSeek Key、修改模型设置后立即生效。

**`app/views/admin.js` / `app/app.css`（系统配置 → AI 策略与模型）**
- 桌面版 / 服务端：Key 输入框始终显示（已配置时提示「输入新 Key 可替换」），新增「DeepSeek 模型」选择（V4.1 Flash / V4 Pro）和「测试连接」按钮，并显示最近一次暂时性错误。
- DSH 插件模式保持原来的「来自 DSH 已配置供应商」选择。

**测试与脚本**
- 新增 `test/llm.test.mjs`（7 项）：用本机模拟服务按官方协议校验模型名、思考参数、截断处理、`reasoning_content` 回传、重试与错误分类、失败不级联、智能体历史。
- `scripts/eval.mjs` 默认模型改为 `deepseek-flash`。

## 四、兼容与合并注意

- **如果本地还有没推送的修复**（尤其是 `core/llm.mjs`），请先推送或告知，再合并本分支，`llm.mjs` 的 OpenAI 兼容部分是整段重写的，容易冲突。
- 旧数据无需迁移：设置里存过的 `deepseek-v4.1-flash` 会自动换成 `deepseek-flash`。
- 外部模型的显示名从 `api.deepseek.com · 模型` 变为 `DeepSeek · 模型`。
- 没有改版本号（仍为 2.4.0），发版时可改为 2.4.1。

## 五、没有改、建议讨论的事项

1. **机密资料的路由策略（影响最大）**：需求文档规定「机密」及以上资料只交给本地模型，没有本地模型时用离线引擎。项目自己的资料（`项目资料/`、`项目工作区/`）默认都是机密，所以**没配本地模型时，起草项目成果一律走离线引擎，填了 DeepSeek Key 也一样**——这很可能是修复后仍会觉得「产出不行」的主要原因。可选：配置本地模型（Ollama 等）；经机构授权后把「密级限制」调到「绝密及以上」；或做「本地模型先脱敏摘要、DeepSeek 再起草」的组合流程。
2. **敏感字段会把整次起草升为机密**：项目只要有金额、估值等字段，`gather()` 就把密级提到机密，整次走离线。需求原文是「敏感字段进入模型前脱敏」，可以考虑外发时脱敏而不是整单降级。
3. **NDA 等标准文书会被当成研究资料**放进提示词，占掉 10 个资料名额中的几个。
4. **Word 历史成果提取不出章节标题**（docx 转文本丢了标题样式），「参考历史成果风格」对 Word 类成果基本不生效。
5. **离线引擎的「财务分析」**会把尽调清单、项目信息表这类表格当作财务表放进去，审计报告里的财务数据反而没解析成表格。
6. 思考强度可以做成设置项（目前起草与智能体固定为 high）。
