架构：加深候选（improve-codebase-architecture）

① 成果生命周期没有唯一归属 Strong 已实施

「谁能在什么状态下对成果做什么」分散在成果模块、AI 起草、智能体保存、接口层与前端，已出现真实分歧（S4、S11）。新增深模块 core/lifecycle.mjs：小接口（check / authorize / actions / holders），背后是状态机与全部权限规则；前端按钮直接由 actions 绘制，不可做时点击说明原因与可操作的人。测试从「搭 HTTP 场景」变成一张判定表。

② 「观看者能看到什么」构造了四次 Strong 已实施

接口、智能体、DSH 工具、AI 汇集各自遮蔽字段，占位符各不相同，org.mask 无人调用（假想 seam）。新增 core/projection.mjs：观看者分为「人」与「代表这个人调用的外部模型」两种适配器——这是有两个适配器的真实 seam。修复了 S3、P3、P4。

③ 流程引擎不发事件，接口层替它补通知 Worth exploring 已实施

引擎现在自己发出 approval.requested / approval.decided，任何调用方（接口、未来的智能体或定时任务）都不会漏通知；表决与结果应用放在同一事务中。

④ 状态与标签字符串前后端重复 Worth exploring 已实施

新增 core/vocab.mjs，经 meta 接口下发，前端同步；「持有 / 继续持有」两种写法统一。

⑤ 前端按岗位上限判断 AI 按钮，后端按策略取低 Speculative 由①顺带解决

工作卡片的 AI 按钮现在用后端对该工作的 aiWrite 判定，不再出现「按钮可点、点了 403」。AI 类内部的依赖回填（ai.engine = engine）保留，未拆分。

可用性改进

  • 项目页「下一步」：逐条列出还差什么、谁负责，轮到你的带「去处理 / 去起草 / 去表决」。
  • 工作台「轮到你」：汇总所有项目中需要你处理的事项。
  • 灰色按钮可点击：说明原因与可以操作的人（不再静默禁用）。
  • 首次使用导览（5 步）与「帮助」中心：三步上手、按岗位用法、名词解释、常见问题。
  • 岗位显示中文名称；切换身份时说明数据范围与 AI 级别；会议可粘贴文字稿；提取确认说明写入去向并提示被覆盖的旧值。
